* 背景

#+BEGIN_QUOTE
Haskell で [[https://atcoder.jp/][AtCoder]] コンテストに参加する人のための記事です。
#+END_QUOTE

Haskell の名前空間は物理的なファイルに対応します。言語によってはファイル内の =namespace= や =mod= 宣言により名前空間を拡張できますが、 Haskell にそのような抜け道は存在しません。

競技プログラミングでは =Main.hs= に相当する **単一のファイル** を提出します。したがって =Main.hs= 以下に各モジュールの内容を展開したものでした:

#+BEGIN_SRC haskell
newQ :: Int -> IO Queue
newQ capacity = do {- ... -}
#+END_SRC

もちろん名前が衝突すればコンパイルエラーとなるため、 =new= ではなく =newQ= とするように、ユニークな名前を設定します。これが Haskell 本来の書き味を損なっており、体験が悪かったです。

* bundler-hs

AI で [[https://github.com/toyboot4e/bundler-hs][bundler-hs]] を作成しました。 [[https://github.com/toyboot4e/bundler-hs][bundler-hs]] は名前空間を考慮して提出ファイルを生成するため、ある程度は元の問題を回避できます。

** インストール

Nix ユーザの方は、 =nix run= により =bundler-hs= を実行できます:

#+BEGIN_SRC sh
alias bundler-hs='nix run github:toyboot4e/bundler-hs --'
#+END_SRC

それ以外の方は、お手数ですが =cabal install= するなどのセットアップが必要です:

#+BEGIN_SRC sh
git clone https://github.com/toyboot4e/bundler-hs # or: ghq get
cd bundler-hs
cabal update
cabal install exe:bundler-hs # ~/.local/bin/bundler-hs
#+END_SRC

** 例: =A.f= と =B.f=

ライブラリ側に同名の関数 =A.f= と =B.f= があるとします:

#+BEGIN_SRC hs
-- ~/MyLibrary/A.hs
f :: Int
f = 10
#+END_SRC

#+BEGIN_SRC hs
-- ~/MyLibrary/B.hs
f :: Int
f = 77
#+END_SRC

これらを =Main.hs= から使用します:

#+BEGIN_SRC hs
-- Main.hs
import A qualified as A
import B qualified as B

main :: IO ()
main = print $ A.f + B.f
#+END_SRC

=Main.hs= を AtCoder 提出用の =Main-Bundled.hs= ファイルに変換します:

#+BEGIN_SRC console
$ bundler-hs --lib ~/MyLibrary Main.hs > Main-Bundled.hs
#+END_SRC

#+BEGIN_SRC hs
main :: IO ()
main = print $ fA + fB

-- ### A
fA :: Int
fA = 10

-- ### B
fB :: Int
fB = 77
#+END_SRC

無事、名前衝突を避けた形に展開されました。このファイルはそのまま AtCoder に提出できます。 **ヤッター！**

** Minify, tree shaking

ライブラリが増えると、提出ファイルが 1,000 行以上のテンプレートを含む場合もあります。問題の解答部分を見やすくするため、 =--minify= 等のオプションを用意しています:

#+BEGIN_SRC sh
bundler-hs \
  --lib ~/MyLibrary \
  --minify-lib --minify-import --minify-language-extensions \
  --tree-shake \
  --no-format \
  --embed-position before \
  Main.hs > Main-Bundled.hs
#+END_SRC

この設定では、以下のような =Main-Bundled.hs= が生成されます:

#+BEGIN_SRC hs
module Main (main) where
fA :: Int ; fA = 10 ; fB :: Int ; fB = 77
main :: IO ()
main = print $ fA + fB
#+END_SRC

巨大なライブラリを使った場合でも、ファイルの 1 行目にすべてのモジュールを埋め込むことができます。

#+BEGIN_QUOTE
より大きなコードの例として、 [[https://atcoder.jp/contests/abc478/submissions/79697747][僕の提出 (例)]] は常に =minify= の設定をしています。 AtCoder アカウントをお持ちの方はご覧いただけます。
#+END_QUOTE

** 注意点

*** フォーマットが保たれない

[[https://github.com/toyboot4e/bundler-hs][bundler-hs]] は [[https://hackage.haskell.org/package/ghc-lib-parser][ghc-lib-parser]] でパースした後の AST に対して、リネーム等の操作をします。 AST から元のソースコードを復元するため、ライブラリ部分のコメントが消え、フォーマットも保たれません。

*** Bundle 後に名前衝突が起きることがある

Import の衝突は自動的に回避されません。たとえば =import Data.Map= のような open import は、 Prelude の =filter= 関数などと名前が衝突します。ライブラリ側の調整が必要になるため、動作確認した方が良いです。

*** その他

- [[https://github.com/toyboot4e/bundler-hs][bundler-hs]] はノールックの AI 生成で運用しています。色々と至らない点もあると思いますが、ご容赦ください。
- [[https://github.com/toyboot4e/bundler-hs][bundler-hs]] は **限定的なユースケースでのみ動作します** 。使うと致命的な問題が見つかると思います (おそらく Windows など……) 。 AI ポン出しの issue で問題ありませんので、見つけた場合はぜひご共有ください。

* まとめ

[[https://github.com/toyboot4e/bundler-hs][bundler-hs]] のおかげでローカルライブラリの qualified import が捌けるようになり、重宝しています。僕自身は [[https://hackage.haskell.org/package/ghc-lib-parser][ghc-lib-parser]] を乗りこなして AST を操作するには腕力が足りませんでしたが、AI が難なくこなしてしまいました。

ご自身でも [[https://github.com/toyboot4e/bundler-hs][bundler-hs]] 相当のツールが手軽に生成できると思いますので、快適な環境でプログラミングして行きましょう！
